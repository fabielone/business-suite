# Operations API security review — 2026-11-17

Scope: the `/v2` operations API (`apps/api/src/app.ts`, `operations.ts`, `operations-auth.ts`, `static-app.ts`), the shared authorization in `packages/core/src/operations/production.ts`, and the row-level security in `db/migrations/002`–`005`. Method: reading the code, then a test for each suspected problem. This is one reviewer's bounded pass (NOTE-020), not a penetration test and not an audit of the `/v1` routes, the clients, the sign-in service or the host.

## Looked at and found sound

- **Cross-site requests.** A request with an `Origin` outside the allow list is refused before any handler runs, cookies are `SameSite=Lax` and `HttpOnly`, and only JSON bodies are accepted. Now covered by a test.
- **Workspace isolation.** Every `/v2` route resolves the workspace through one function that checks active membership inside the transaction and locks it against a concurrent revocation. Row-level security on every workspace table is keyed to the same transaction setting. Read in the migrations; the real-PostgreSQL suite was not re-run.
- **Sign-in tokens.** Issuer, audience, expiry, algorithm and subject are checked; the service token the API signs for account activation has none of these and cannot be used as a person.
- **Internal commands** (`task.alert`, `notification.create`, `automation.note`) are refused unless an automation issued them.
- **Lead intake.** Keys are stored hashed, allow only adding leads, cannot create team members, and redirect only to an origin the key lists.
- **Static files.** Path traversal and unknown file types are refused; a content security policy is set.

## Not covered

`/v1` routes, mobile and desktop clients, the browser's encrypted offline vault, the sign-in service configuration, reverse proxy and TLS settings, dependency advisories beyond `npm audit`, load behaviour, and any testing from outside the process.
